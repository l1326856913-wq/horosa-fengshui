# Horosa FengShui AR

实时风水堪舆系统：手机摄像头多帧空间序列 + 罗盘 / 卫星地图拉线定向，后端 `mingyu-core` 引擎完成玄空飞星 + 八宅明镜排盘，前端调用多模态大模型结合多角度实景进行整体空间堪舆分析。iOS PWA 风格，暗黑金 AR HUD。

## 目录结构（实际）

```
horosa-fengshui/
├── api/
│   └── index.js          # Vercel Serverless：/api/health、/api/horosa（排盘）、/api/map（高德静态图）、/api/ai（大模型流式代理）
├── public/
│   ├── index.html        # iOS PWA 前端：摄像头 AR、EMA 罗盘滤波、Leaflet 卫星图拉线定向、流式对话
│   ├── manifest.json     # PWA 配置
│   └── icon-*.png        # PWA 图标
├── dev-server.mjs        # 本地开发服务器（模拟 Vercel 环境）
├── test-engine.mjs       # mingyu-core 排盘引擎验证脚本
├── package.json
└── vercel.json           # Vercel 部署配置
```

## 运行方式

### 本地运行

```bash
npm install
node dev-server.mjs 8000
# 浏览器访问 http://localhost:8000
```

### Vercel 部署

```bash
npm i -g vercel
vercel        # 预览环境
vercel --prod # 生产环境
```

部署后必须使用 HTTPS 访问（Vercel 默认满足），否则手机无法授予摄像头与罗盘权限。

## 关键设计（防止幻觉与误差）

1. **八方位定向采集替代单帧**：先罗盘锁定基准，再引导依次对准 8 个罗盘方位（正北/东北/正东/东南/正南/西南/正西/西北，±12° 内稳定 0.8 秒自动拍摄，可跳过），每帧按"方位→九宫→飞星"与排盘映射解读；系统指令含八方位-九宫映射铁律（禁止把不同帧误判为不同房间）。
2. **理气与断语分离**：所有坐向、飞星、命卦均由 `mingyu-core` 确定性引擎计算，AI 只做解读，System Instruction 明确禁止 AI 重算或改写排盘数字；回复中的山向/命卦表述经前端机器交叉核对，不一致即亮黄牌。
3. **磁偏角自动修正**：手机罗盘输出磁北方位，后端按 GPS 坐标用 WMM（`geomagnetism`）计算当地磁偏角换算真北（北京约 -7.5°，不修正足以错判一整山）。
4. **双定向模式**：卫星地图拉线定向直接得到真北方位角（无需磁偏角）；罗盘模式走磁偏角修正链路。
5. **测量误差显式建模**：罗盘 ±3°；地图拉线按线长动态估算点选误差（下限 ±1.5°，拉线过短会强警示），读数靠近二十四山分界或下卦/兼向边界时，引擎返回候选山向与复测警示而非强行下断。
6. **引擎业务校验**：缺建造年、缺 GPS、度数越界等情况返回可读的 400 提示，不伪造数据。
7. **两步站位指引与室内外口径匹配**：先选勘测环境（室外/室内），再选该环境下的站位方式（室外·门外定向 / 室内·立极环拍 / 室内·区域复查）；环境与站位注入 prompt，AI 按对应口径解读。
8. **补拍闭环**：AI 判断画面不足时输出【重拍请求】，前端出现补拍按钮；补拍序列以【第N轮补拍】追加进对话，AI 带前轮记忆整合分析（单次勘测最多 3 轮）。
9. **勘测记忆**：每次分析结论自动留存（时间/方式/坐向/运/命卦/摘要，保留最近 2 条），下次勘测自动注入，冲突以本轮实测为准；📜 按钮可查看与清除。

## 核心接口

- `POST /api/horosa`：`{ heading, northReference: 'magnetic'|'true', lat?, lng?, year(建造年), birthYear?, gender?, uncertainty? }` → 玄空 + 八宅完整排盘与结构化证据提示词
- `POST /api/ai`：`{ provider: 'gemini'|'deepseek'|'glm', apiKey, payload }` → 流式转发大模型 SSE（规避浏览器 CORS）
- `POST /api/map`：`{ lat, lng, gaode_key }` → 高德静态外局图 base64
- `GET /api/health`：健康检查

## 模型说明（2026-10 核实）

- Gemini：`gemini-3.1-pro-preview`
- DeepSeek：`deepseek-chat`（纯文本，自动降级为纯理气盲算）
- 智谱：`glm-5.3-flash`（原生多模态，支持图像输入；`glm-5.3` 旗舰为纯文本，勿用于看图）

## 准确性修复记录（2026-10-04）

本项目在 2026-10-04 完成了一轮全维度深度拆解（产物见 `analysis/`），并落地修复了 4 个 P0 与 7 个第二阶段加固项。**改动前存在一处会导致整张飞星盘作废的坐向缺陷**，若你此前基于旧版本得到过结论，建议重测。

### P0（致命，已修）

| 问题 | 根因 | 修复 |
|---|---|---|
| **采集污染坐向基准** | `lockAndAnalyze()` 在八方位采集**结束后**才读 `currentHeading` 作坐向，而采集已把它改写为最后一个采集方位，偏差 20°~45°（2~3 个山位） | 采集前冻结 `baseHeading`，采集后恢复 `currentHeading`；实测正确率由 0/12 → 12/12 |
| **请求体守卫失效** | 守卫设 8MB，但 Vercel 平台硬上限约 4.5MB，请求在到达函数前已被平台拒绝 | 守卫改 4MB；图片 720px/q0.8 → 512px/q0.65；新增历史图片裁剪（仅留最近 2 轮）与发送前体积预检 |
| **室内模式坐向来源错误** | 立极环拍时用户朝向任意，该角度被当坐向排盘，且被铁律禁止 AI 质疑 | 新增 `HOROSA_SITUATING` 落盘机制，室内强制复用室外已确认坐向；无记录时拦截并引导先做室外定向 |
| **无 GPS 时罗盘不可用** | 磁偏角缺 GPS 直接 400，无降级路径，室内场景 100% 不可达 | 定位改为可等待 + 超时提示，失败自动切地图拉线模式（真北无需修正），排盘前二次拦截并给可执行指引 |

### 第二阶段（准确性加固，已修）

| 问题 | 修复 |
|---|---|
| **九运/八运分界未按立春** | 引擎 `resolveXuanKongPeriod` 按公历年切分（其源码注释亦承认是近似），导致 1/1~立春建造的房子误入下一运。现用 tyme4ts 计算立春精确时刻，在调用引擎前修正年份。**2024-01-15 建造现正确判为八运**（修复前误判九运） |
| **命卦口径未声明** | 引擎用「年份除九取余 + 11/4」，与民间「数字和法」结果半数不同。现于 meta 返回 `mingGuaMethod` 并在排盘面板标注 |
| **引擎不确定性被丢弃** | 引擎诚实返回的「距分界仅 X°，可能为 A/B 两条山」此前被前端丢弃。现于九宫格上方显示橙色警示横幅与复测建议 |
| **45s 看门狗误杀深度思考** | 改两级：首字节 90s，之后每字节重置 45s；思考心跳改为请求发出即启动（原为收到 reasoning 才显示，恰在最需要时不显示） |
| **勘测记忆污染** | 思考流兜底/超时/空回复一律不写入记忆；记忆新增 `verified`/`sitDegree`/`orientationSource`，并在注入 AI 与记忆面板中标注可信度 |
| **提示词重复条款** | 删除重复的铁律 K；修正 `STAR_RULES` 中「六白忌火性物品」的理由（原文误写「火克金」，引擎实为**金克火**） |

### 设置项变更

新增「**住宅建造月/日**」（可选但强烈建议）：三元九运按**立春**交运，仅填年份时若住宅恰建于 1/1~立春区间（每年约 34 天）会被误判入下一运，整张飞星盘作废。八宅命卦原本已严格按立春判定，本次修正后两者时间标准已统一。

## 第三阶段：知识层可追溯性加固（2026-10-04）

第二阶段修完运界后，复检发现**紫白流年盘仍按公历年干支**——而干支年本身以立春换界（实测 `SixtyCycleYear.fromYear(2024)` 返回甲辰年而非甲子年）。结果是同一张盘出现两套时间标准：运界已回退到 2023，流年却仍取 2024。本阶段连同三项残留问题一并修复。

| 问题 | 根因 | 修复 |
|---|---|---|
| **流年盘未按立春换年** | `resolveYearFlyingStar(year)` 只收年份，内部用公历年号取以立春为界的干支年，每年 1/1~立春期间流年星错一星 | 新增 `resolveFlowYearByLichun()`；补齐流年参照月/日即走引擎节气年路径（该路径本身正确）。实测 `2026-01-15` 由一白修正为二黑（2025 干支年） |
| **星性宜忌表无出处** | `STAR_RULES` 九条宜忌全表硬编码在前端，无一条标注流派依据；`remindersPanel` 却标注「确定性规则，非AI生成」，实为本地常量 | 九条全部补 `source`（引《协纪辨方书》或明示「各家共识」）与 `wuxing`；标注改为诚实表述「本地通行星性口径归纳表，非引擎输出」，并声明流派差异；UI 增设〔依据〕悬停提示 |
| **重拍按钮可能误触发** | `reply.includes('【重拍')` 纯字符串匹配，而兜底路径下 `fullReply` 是**思考流**，其中出现「重拍」二字即误触发 | 新增统一门控 `isFormalReply(reply)`，以 `__meta.formal` 判定；首轮、补拍轮、以及两处记忆写入全部改用该门控 |
| **城门诀推导被丢弃** | 前端只渲染 `castleGate.summary` 一句结论，引擎给出的完整推导链全部丢弃，用户无法区分「此盘无城门」是算错还是格局如此 | 展开 `candidates`：逐条显示正/副城门、运星、顺逆飞向、飞临星、判定结论；无城门时明示「属格局本身如此，非排盘错误」 |

### 顺带修掉的一处安全隐患

复检星性表转义时发现：排盘面板存在**引擎字段未转义**直接插入 `innerHTML` 的情况（`p.name`、`p.direction`、`p.shanXiangRelation`、`x.period.label`、`b.mingGua`、四吉位 `d.direction`/`d.label` 等）。虽当前引擎输出均为纯文本、未构成实际风险，但一旦上游返回含尖括号的字符串即会破坏 DOM。现已全部收敛到 `escHtml(String(...))`。

### 新增设置项

「**流年参照月/日**」（可选）：与建造月/日同理，流年紫白按立春换年。若所填为当年且在 1/1~立春之间，填「今天」即可对齐；不填则按公历年判定并在罗盘面板给出边界告警。

## 已知风险与维护清单

**数据层**
- `geomagnetism` 内置 WMM-2025 地磁模型，**有效期至 2029 年 11 月**。过期后库会静默用旧模型外推（每年约漂移 0.1°），届时需升级该依赖或换用官方 WMM 新版。

**部署层**
- `vercel.json` 已设函数 `maxDuration: 300`（Hobby 上限；Pro 可更高）。AI 长回答依赖流式透传，若函数被提前截断，调高此值。
- API 无鉴权无限流，公开部署后任何人都可消耗你的函数配额。商用前建议加 IP 限流（如 Vercel Firewall / Upstash Rate Limit）。
- 高德 Key 建议在高德控制台绑定域名白名单，防止盗用。

**隐私与合规**
- 应会上传 GPS 坐标、罗盘读数、室内照片至所选大模型服务商（用户自己的 Key）。需在产品页明示并取得用户同意；商用前补充隐私政策与免责声明。
- AI 密钥存于浏览器 localStorage，存在 XSS 窃取面；面向公众商用时应改为服务端密钥 + 用户体系。

**测量操作层（准确性的最大变量）**
- 手机罗盘受金属、磁铁、手机壳、车内环境影响极大，测量前务必画"8"字校准并远离干扰源（App 已内置提示）。
- 读数落在二十四山分界或下卦/兼向边界（±4.5°）时，以引擎返回的候选山向警示为准，必须复测。
- 建造年、起运年、入宅年口径不同会导出不同运盘，填写前应确认采用哪一口径。

**免责声明**
本项目的排盘与 AI 分析结果仅供传统环境文化研究与参考，不构成建筑、装修、投资、医疗或其他专业决策依据。
